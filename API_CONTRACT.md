# API-контракт: Портал отпусков и командировок (Frontend ↔ 1С)

## 1. Общие требования к HTTP-сервису 1С
1. **Базовый префикс URL:** `/api/v1` (например: `http://<server>/<base>/hs/api/v1`).
2. **Формат данных:** `Content-Type: application/json; charset=utf-8`.
3. **Именование полей:** строго `camelCase` (`dateFrom`, `fullName`, `dailyAllowance`).
4. **Формат дат:** ISO 8601 (`"YYYY-MM-DD"` для дат начала/окончания, `"YYYY-MM-DDTHH:mm:ssZ"` для времени уведомлений).
5. **Авторизация:** Все эндпоинты (кроме `/auth/login` и `/auth/refresh`) требуют заголовок:
   `Authorization: Bearer <accessToken>`
6. **CORS:** На сервере 1С (или веб-сервере перед ним) должны быть разрешены запросы с фронтенда (`Access-Control-Allow-Origin`, `Access-Control-Allow-Methods: GET, POST, PUT, PATCH, OPTIONS`, `Access-Control-Allow-Headers: Content-Type, Authorization`).
7. **Формат ошибок:** При любом коде ошибки (`400`, `401`, `403`, `404`, `500`) возвращать JSON вида:
   ```json
   {
     "message": "Человекочитаемый текст ошибки для вывода пользователю"
   }
   ```

## 2. Авторизация и профиль

### 2.1. Вход в систему
* **Метод и URL:** `POST /api/v1/auth/login`
* **Тело запроса:**
  ```json
  {
    "email": "ivanov@company.ru",
    "password": "user_password"
  }
  ```
* **Успешный ответ (`200 OK`):**
  *(Роль `role` принимает строго одно из двух значений: `"employee"` или `"employer"`)*
  ```json
  {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "dGhpcyBpcyBhIHJlZnJlc2g...",
    "user": {
      "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "email": "ivanov@company.ru",
      "fullName": "Иванов Иван Иванович",
      "role": "employee",
      "department": "Отдел разработки",
      "position": "Frontend-разработчик"
    }
  }
  ```
* **Ошибка (`401 Unauthorized`):** `{ "message": "Неверный email или пароль" }`

### 2.2. Обновление JWT-токена
* **Метод и URL:** `POST /api/v1/auth/refresh`
* **Тело запроса:**
  ```json
  {
    "refreshToken": "dGhpcyBpcyBhIHJlZnJlc2g..."
  }
  ```
* **Успешный ответ (`200 OK`):**
  ```json
  {
    "accessToken": "new_access_token...",
    "refreshToken": "new_refresh_token..."
  }
  ```

### 2.3. Получение текущего пользователя (восстановление сессии)
* **Метод и URL:** `GET /api/v1/auth/me`
* **Успешный ответ (`200 OK`):**
  ```json
  {
    "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "email": "ivanov@company.ru",
    "fullName": "Иванов Иван Иванович",
    "role": "employee",
    "department": "Отдел разработки",
    "position": "Frontend-разработчик"
  }
  ```

## 3. Заявки на отпуск и командировки

### 3.1. Получение списка заявок
* **Метод и URL:** `GET /api/v1/requests`
* **Логика 1С:**
  * Если токен принадлежит **работнику (`employee`)** — вернуть все его заявления (активные и архивные).
  * Если токен принадлежит **работодателю (`employer`)** — вернуть все заявления его подчиненных.
* **Возможные значения полей:**
  * `type`: `"vacation"` (отпуск) | `"trip"` (командировка)
  * `status`: `"pending"` (на рассмотрении) | `"revision"` (на доработке) | `"approved"` (согласовано) | `"rejected"` (отказано)
* **Успешный ответ (`200 OK`):**

      "number": "12345",
      "type": "vacation",
      "status": "pending",

      "dateTo": "2026-12-24",

### 3.2. Получение детальной информации по заявке (и аналитики для работодателя)
* **Метод и URL:** `GET /api/v1/requests/:id`
* **Успешный ответ (`200 OK`):**
  *(Блок `analytics` обязателен при запросе от работодателя для отрисовки диаграммы и оценки влияния на странице согласования)*

    "dateTo": "2026-12-02",

    "comment": null,

    "employee": {
      "id": "emp-001",
      "fullName": "Иванов Иван Иванович",

      "recommendationText": "Сотрудника можно отпустить: критических релизов на эти даты не запланировано."

### 3.3. Создание нового заявления (работник)
* **Метод и URL:** `POST /api/v1/requests`
* **Тело запроса (для отпуска):**
  ```json
  {
    "type": "vacation",
    "dateFrom": "2026-12-10",
    "dateTo": "2026-12-24",
    "reason": "Ежегодный оплачиваемый отпуск"
  }
  ```
* **Тело запроса (для командировки):**
  ```json
  {
    "type": "trip",
    "dateFrom": "2026-12-10",
    "dateTo": "2026-12-15",
    "dailyAllowance": 2000,
    "destination": "г. Казань, Технопарк",
    "reason": "Участие в профильной конференции"
  }
  ```
* **Успешный ответ (`201 Created` или `200 OK`):** созданный объект заявки со статусом `"pending"`.

### 3.4. Редактирование заявления после возврата на доработку (работник)
* **Метод и URL:** `PUT /api/v1/requests/:id`
* **Логика 1С:** Обновляет поля заявки и автоматически переводит её статус обратно в `"pending"`.
* **Тело запроса:**
  ```json
  {
    "dateFrom": "2026-12-12",
    "dateTo": "2026-12-16",
    "dailyAllowance": 2500,
    "destination": "г. Казань, Технопарк",
    "reason": "Уточнённая цель поездки"
  }
  ```
* **Успешный ответ (`200 OK`):** обновленный объект заявки.

### 3.5. Принятие решения по заявке (работодатель)
* **Метод и URL:** `PATCH /api/v1/requests/:id/decision`
* **Логика 1С:** Меняет статус заявки, сохраняет комментарий руководителя, отправляет email-уведомление сотруднику и создает запись в списке уведомлений на портале.
* **Тело запроса:**
  *(Поле `decision` принимает значения: `"approved"` | `"revision"` | `"rejected"`)*
  ```json
  {
    "decision": "approved",
    "comment": "Согласовано, хорошего отдыха!"
  }
  ```
* **Успешный ответ (`200 OK`):** обновленный объект заявки.

## 4. Справочники и Уведомления

### 4.1. Справочники отделов и должностей (для фильтров работодателя)
* **Метод и URL:** `GET /api/v1/dictionaries`
* **Успешный ответ (`200 OK`):**
  ```json
  {
    "departments": ["Отдел разработки", "Отдел дизайна", "Бухгалтерия"],
    "positions": ["Frontend-разработчик", "Backend-разработчик", "Дизайнер"]
  }
  ```

### 4.2. Список уведомлений работника
* **Метод и URL:** `GET /api/v1/notifications`
* **Возможные значения `status`:** `"approved"` (галочка) | `"rejected"` (крестик) | `"pending"` (часики)
* **Успешный ответ (`200 OK`):**
  ```json
  [
    {
      "id": "notif-1",
      "status": "approved",
      "text": "Ваше заявление #12346 (Командировка) было согласовано руководителем.",
      "createdAt": "2026-11-16T09:15:00Z",
      "isRead": false
    }
  ]
  ```

### 4.3. Отметка всех уведомлений как прочитанных
* **Метод и URL:** `PATCH /api/v1/notifications/read-all`
* **Логика 1С:** Помечает все уведомления текущего пользователя как прочитанные (`isRead = true`).
* **Успешный ответ (`200 OK`):** `{ "success": true }`


## 5. Важные технические нюансы для разработчиков 1С

1. **Пустые списки — только `[]`, никогда `null`!**
   В 1С при сериализации в JSON пустая коллекция или `Неопределено` часто превращается в `null`. Если у сотрудника нет заявок или уведомлений, 1С должна возвращать пустой массив `[]`, иначе фронтенд упадет с ошибкой при попытке отрисовать список.
2. **Обработка метода `OPTIONS` для CORS.**
   Поскольку фронтенд передает заголовок `Authorization: Bearer ...` и использует методы `PUT` и `PATCH`, браузер перед каждым таким запросом отправляет проверочный `OPTIONS`-запрос. В шаблонах URL HTTP-сервиса 1С (или в настройках Apache/IIS) обязательно должен быть разрешен метод `OPTIONS` без проверки токена авторизации (возвращающий статус `200 OK` и CORS-заголовки).
3. **Поддержка методов `PUT` и `PATCH` на веб-сервере.**
   В стандартной публикации 1С на IIS методы `PUT` и `PATCH` иногда заблокированы по умолчанию. Нужно убедиться, что веб-сервер пропускает их в HTTP-сервис 1С (либо заранее согласовать замену на `POST`, если администрирование IIS ограничено).
4. **Время жизни JWT-токенов.**
   Рекомендуемое время жизни: `accessToken` — **15–30 минут**, `refreshToken` — **7–30 дней**. При истечении `accessToken` 1С должна возвращать строго HTTP-статус **`401`** (а не `403` или `500`), чтобы перехватчик Axios на фронтенде автоматически обновил токен без разлогина пользователя.
5. **Генерация номера и ID заявки.**
   Поля `id` (UUID объекта в 1С) и `number` (номер документа в 1С) генерируются на стороне 1С при вызове `POST /api/v1/requests` и возвращаются в ответе.
